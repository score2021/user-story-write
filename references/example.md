# 资产月报与风险分析助手

以下为假设案例；输入条件为方案已确认支持自托管。具名产品的当前能力需在实际使用时核实，此处只示范比较角度。

**S｜用户背景**

小林是资产管理软件公司的开发者。客户每月都要核对资产变化、整理月报和风险清单，希望在原系统中自动完成，并能继续追问原因。

**C｜用户痛点与现有方案局限**

人工整理耗时，发现异常还要反复查询。小林考虑了几种方案：

- **直接接入模型 API：** 能总结数据，但工具调用、任务状态和报告交付仍需自己建设。
- **自行部署 OpenClaw（小龙虾）：** 可以增加控制力，但环境维护、权限隔离和升级仍需团队承担。
- **采用 WorkBuddy 等现成企业助手：** 能辅助分析，但部署方式、接口和数据边界是否适合嵌入资产产品，仍需评估与集成。

**Q｜需要解决的问题**

怎样在客户可控的环境中，减少重复开发与运维，更快交付一个融入资产系统的分析助手？

**A｜Managed Agent 如何解决**

小林将 Managed Agent 自托管在客户环境中，通过 Skill 定义分析步骤和风险规则，通过 MCP 或工具连接资产数据。资产系统定时通过 API 发起任务，平台组织查询、计算和报告生成，管理运行状态与会话上下文，支持客户在原系统中继续追问。

**最终价值与边界**

资产负责人减少重复整理，更快获得有依据的报告；开发团队减少 Agent 运行能力的重复建设；客户通过自托管掌控运行环境与数据访问边界。

客户仍需负责业务权限、风险规则和实际处置。自托管仍有基础设施运维成本，数据是否出内网取决于模型与外部服务配置。
